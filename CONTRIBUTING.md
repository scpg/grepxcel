# Contributing to grepxcel

Thanks for your interest in contributing!

## Branch model

| Branch | Purpose |
|---|---|
| `main` | Stable, always green. Never commit directly — changes arrive via PR from `dev`. |
| `dev` | Active development. **All pull requests target this branch.** |

## Step-by-step guide

### 1. Fork the repository

Click **Fork** on the top-right of the GitHub page. GitHub creates your own copy of the repo under your account.

### 2. Clone your fork

```bash
git clone https://github.com/<your-username>/grepxcel.git
cd grepxcel
```

### 3. Set up the development environment

```bash
python -m venv .venv

# Core dependencies + test runner
.venv/bin/pip install -r requirements.txt -r requirements-dev.txt

# Optional: install the draft feature (heavy — compiles C++ code for local LLM)
# .venv/bin/pip install -r requirements-draft.txt
# Or use the hardware-aware installer (detects CUDA/Metal automatically):
# python3 scripts/install_llm_deps.py
```

### 4. Create a branch from `dev`

Always branch off `dev`, never off `main`.
Use the naming convention `<type>/<description>/<github-user>`:

| Type | When to use |
|---|---|
| `feature/` | New user-visible functionality |
| `fix/` | Bug fix (non-urgent) |
| `hotfix/` | Urgent production patch — **branches off `main`**, not `dev` |
| `chore/` | Dependency bumps, config, tooling, cleanup |
| `refactor/` | Code restructure with no behaviour change |
| `docs/` | Documentation only |
| `test/` | Tests only |
| `ci/` | CI/CD pipeline changes |

`<description>` should be a short kebab-case phrase (2–4 words).
`<github-user>` is your GitHub username.

```bash
git checkout dev
git pull origin dev

# examples
git checkout -b feature/flat-tables-option/octocat
git checkout -b fix/audit-sheet-misclassification/octocat
git checkout -b chore/bump-openpyxl/octocat
git checkout -b docs/mcp-setup-guide/octocat
```

**Exception — hotfix:** branch off `main` and PR directly back to `main`
(the maintainer will then merge `main` → `dev` to keep them in sync):

```bash
git checkout main
git pull origin main
git checkout -b hotfix/sbom-crash-on-missing-dist/octocat
```

### 5. Make your changes

A few rules:

- No inline `python -c "..."` scripts — put any one-off code in `tmp.local/`
- snake_case for variables/functions, CamelCase for classes
- Maximum line length: 88 characters
- All tests must pass before opening a PR

### 6. Run the tests

```bash
.venv/bin/pytest tests/ -q
```

### 7. Push and open a Pull Request

```bash
git push origin feature/your-feature-name/your-username
```

Then open a PR on GitHub. **Set the base branch to `dev`**, not `main`:

```
your-fork:feature/your-feature-name/your-username  →  scpg/grepxcel:dev
```

In the PR description include:

- What the change does and why
- Any test evidence (new test added, or existing test output)

## CI

GitHub Actions runs the full test suite on every push and PR. Your PR must be green before it can be merged.

## Test fixtures

Every fixture in `tests/fixtures/<N>_<name>/` may contain the following files:

| File pattern | Purpose | Editable by tooling? |
|---|---|---|
| `<name>_data.xlsx` | Source Excel file the engine extracts from | ✅ |
| `<name>_data-cdr.xlsx` | Security CDR copy — macros, VBA, and external links stripped by OPSWAT MetaDefender. Used to test the security layer. | ✅ |
| `<name>_pattern-from-draft.xlsx/.csv` | Legacy baseline pattern (programmatic for 01–14, original `grepxcel draft` output for 15–22). Both formats kept in sync. | ✅ |
| `<name>_pattern-from-claude.xlsx/.csv` | Pattern generated by Claude API backend. Produced by `scripts/regenerate_drafts.py --backend claude`. | ✅ |
| `<name>_pattern-from-local.xlsx/.csv` | Pattern generated by local LLM backend (llama-cpp). Produced by `scripts/regenerate_drafts.py --backend local`. | ✅ |
| `<name>_pattern-from-github.xlsx/.csv` | Pattern generated by GitHub Models backend. | ✅ |
| `<name>_pattern-manual.xlsx` | Hand-crafted pattern by the project maintainer. **Never overwrite or regenerate.** | ❌ read-only |
| `<name>_snapshot-from-<backend>.json` | Stored extraction output for `pattern-from-<backend>.*`. Used by `test_snapshots.py` for regression testing. Regenerate with `scripts/generate_snapshots.py`. | ✅ intentional only |
| `<name>_snapshot-manual.json` | Stored extraction output for `pattern-manual.xlsx`. | ✅ intentional only |

The `docs/pattern-reference.xlsx` is a **committed build artifact** generated by `grepxcel docs -o docs/pattern-reference.xlsx`. Regenerate it after any pattern-format change and include it in your PR.

## API keys and environment

Two `.env` template files are provided:

| File | Use case |
|---|---|
| `.env.example` | Minimal template — covers the three API keys (`ANTHROPIC_API_KEY`, `GOOGLE_API_KEY`, `GITHUB_TOKEN`). Copy to `.env` and fill in your keys. |
| `.env.template` | Extended template for 1Password / Snyk workflows. Includes Snyk org/project IDs. Use this if you run `op run --env-file=.env` or use Snyk in CI. |

Both `.env` and `.env.template` are gitignored — never commit real keys.
